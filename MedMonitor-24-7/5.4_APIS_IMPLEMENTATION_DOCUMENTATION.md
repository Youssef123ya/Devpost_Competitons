## 5.4.1 Auth & Account Management APIs

### Overview
The authentication and account management subsystem provides secure credential validation and session management for medical staff (doctors, nurses, and ICU administrators). All API requests except login/logout require a valid JWT bearer token.

---

### 5.4.1.1 POST /api/Account/login

**Purpose:** Authenticates medical staff credentials and issues a JWT access token for secure API communication.

**HTTP Method:** POST  
**Authorization Required:** No (Public endpoint)

#### Request Requirements

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| email | String | Yes | Medical staff email address (e.g., dr.ahmed@medmonitor.local) |
| password | String | Yes | Account password (minimum 8 characters) |
| deviceId | String | Optional | Unique device identifier for multi-device session tracking |

**Request Body Sample:**
```json
{
  "email": "dr.ahmed.abdel@medmonitor.local",
  "password": "SecurePass123!",
  "deviceId": "DEVICE_IPAD_001"
}
```

#### Response Body Sample

**Success Response (200 OK):**
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Login successful",
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "refreshToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "expiresIn": 3600,
    "staffId": "STAFF_001",
    "name": "Dr. Ahmed Abdel-Nasser",
    "role": "Doctor",
    "department": "ICU",
    "profilePicture": "https://medmonitor.local/uploads/staff/STAFF_001.jpg"
  }
}
```

**Error Response (401 Unauthorized):**
```json
{
  "success": false,
  "statusCode": 401,
  "message": "Invalid email or password",
  "errors": ["Authentication failed"]
}
```

#### HTTP Status Codes

| Code | Scenario |
|------|----------|
| 200 OK | Successful authentication and token issued |
| 400 Bad Request | Missing or invalid request parameters |
| 401 Unauthorized | Invalid credentials or account locked |
| 403 Forbidden | Staff account inactive or revoked permissions |
| 429 Too Many Requests | Multiple failed login attempts detected (security lockout) |
| 500 Internal Server Error | Database or authentication service failure |

#### Authorization & Role Access
- **Allowed Roles:** Doctor, Nurse, ICU Admin, System Administrator
- **Token Type:** JWT Bearer Token (valid for 1 hour)
- **Session Management:** Refresh token valid for 7 days

---

### 5.4.1.2 POST /api/Account/logout

**Purpose:** Invalidates the current JWT session and clears authentication tokens from the server-side token blacklist.

**HTTP Method:** POST  
**Authorization Required:** Yes (JWT Bearer Token)

#### Request Requirements

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| (JWT Token) | Header | Yes | Authorization header: `Bearer {accessToken}` |
| deviceId | String | Optional | Device identifier to logout from specific device only |

**Request Body Sample:**
```json
{
  "deviceId": "DEVICE_IPAD_001"
}
```

#### Response Body Sample

**Success Response (200 OK):**
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Logout successful. Session terminated.",
  "data": {
    "staffId": "STAFF_001",
    "logoutTime": "2026-06-02T14:35:22Z"
  }
}
```

#### HTTP Status Codes

| Code | Scenario |
|------|----------|
| 200 OK | Session successfully terminated |
| 400 Bad Request | Invalid token or malformed request |
| 401 Unauthorized | Token expired or already invalidated |
| 500 Internal Server Error | Server-side session management failure |

#### Authorization & Role Access
- **Allowed Roles:** Doctor, Nurse, ICU Admin, System Administrator
- **Token Type:** JWT Bearer Token (must be valid)

---

## 5.4.2 Patient Management APIs

### Overview
The patient management subsystem handles ICU patient admission, discharge, profile retrieval, and clinical data updates. These APIs maintain comprehensive patient electronic medical records (EMR) including demographics, medical history, current medications, and admission/discharge status.

---

## 5.4.3 Vital Signs & OCR Telemetry APIs

### Overview
The vital signs and OCR telemetry subsystem captures real-time physiological measurements extracted from patient monitoring cameras (HOOD W 501) via optical character recognition (OCR) processing. This subsystem maintains historical vital signs data and enables real-time clinical decision support.

---

### 5.4.3.1 POST /api/VitalSigns/Telemetry

**Purpose:** Receives real-time physiological measurements extracted via OCR from monitoring cameras and stores them in time-series database for patient observation and automated alert triggering.

**HTTP Method:** POST  
**Authorization Required:** Yes (Device API Key or JWT Bearer Token)

#### Request Requirements

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| deviceId | String | Yes | HOOD W 501 camera hardware identifier |
| patientId | String | Yes | ICU patient identifier being monitored |
| heartRate | Integer | Yes | Beats per minute (normal range: 60-100 bpm) |
| systolicBP | Integer | Yes | Systolic blood pressure in mmHg |
| diastolicBP | Integer | Yes | Diastolic blood pressure in mmHg |
| oxygenSaturation | Integer | Yes | SpO2 percentage (normal range: 95-100%) |
| temperature | Float | Yes | Core body temperature in Celsius (normal: 36.5-37.5°C) |
| respiratoryRate | Integer | Yes | Breaths per minute (normal range: 12-20 bpm) |
| timestamp | DateTime | Yes | UTC timestamp of measurement capture |
| confidenceScore | Float | Optional | OCR reading confidence (0.0-1.0 scale, default: 1.0) |

**Request Body Sample:**
```json
{
  "deviceId": "CAM_HOOD_001",
  "patientId": "PAT_20260602_001",
  "heartRate": 78,
  "systolicBP": 128,
  "diastolicBP": 82,
  "oxygenSaturation": 96,
  "temperature": 37.2,
  "respiratoryRate": 16,
  "timestamp": "2026-06-02T14:35:22Z",
  "confidenceScore": 0.98
}
```

#### Response Body Sample

**Success Response (201 Created):**
```json
{
  "success": true,
  "statusCode": 201,
  "message": "Vital signs telemetry recorded successfully",
  "data": {
    "vitalSignsId": "VITALS_20260602_001",
    "deviceId": "CAM_HOOD_001",
    "patientId": "PAT_20260602_001",
    "recordedDateTime": "2026-06-02T14:35:22Z",
    "heartRate": 78,
    "systolicBP": 128,
    "diastolicBP": 82,
    "oxygenSaturation": 96,
    "temperature": 37.2,
    "respiratoryRate": 16,
    "clinicalStatus": "Stable",
    "alertsTriggered": []
  }
}
```

**Error Response (400 Bad Request):**
```json
{
  "success": false,
  "statusCode": 400,
  "message": "Invalid vital signs reading",
  "errors": [
    "Oxygen saturation 45% is critically low and requires immediate medical attention",
    "Heart rate 180 bpm exceeds safe threshold"
  ],
  "alertsTriggered": ["CRITICAL_HYPOXIA", "TACHYCARDIA"]
}
```

#### HTTP Status Codes

| Code | Scenario |
|------|----------|
| 201 Created | Vital signs recorded and stored successfully |
| 400 Bad Request | Invalid vital signs data or out-of-range values |
| 401 Unauthorized | Invalid device key or JWT token |
| 403 Forbidden | Device not authorized for this patient |
| 404 Not Found | Device or patient does not exist |
| 409 Conflict | Multiple simultaneous readings from same device |
| 500 Internal Server Error | Time-series database write failure |

#### Authorization & Role Access
- **Allowed Roles:** Device API (HOOD W 501 Camera), Doctor, Nurse, ICU Admin
- **Device Authentication:** Device API Key with hardware serial number validation
- **Token Type:** JWT Bearer Token or Device-specific API Key

#### Clinical Alert Thresholds

The system automatically triggers alerts if readings fall outside safe parameters:

| Parameter | Critical Low | Warning Low | Normal | Warning High | Critical High |
|-----------|---|---|---|---|---|
| Heart Rate (bpm) | < 40 | 40-60 | 60-100 | 100-120 | > 120 |
| SpO2 (%) | < 80 | 80-90 | 95-100 | N/A | N/A |
| Systolic BP (mmHg) | < 90 | 90-100 | 100-140 | 140-160 | > 160 |
| Temperature (°C) | < 35 | 35-36.5 | 36.5-37.5 | 37.5-39 | > 39 |
| Respiratory Rate (bpm) | < 8 | 8-12 | 12-20 | 20-30 | > 30 |

## 5.4.8 API General Specifications

### Common Response Format

All API responses follow a standardized envelope format:

```json
{
  "success": Boolean,
  "statusCode": Integer,
  "message": String,
  "data": Object (or Array),
  "errors": Array (optional, only in error responses)
}
```

### Authentication & Authorization

- **JWT Bearer Token:** All authenticated endpoints require `Authorization: Bearer {token}` header
- **Token Lifespan:** 1 hour; refresh tokens valid for 7 days
- **Role-Based Access Control (RBAC):** Enforced per endpoint based on user role
- **Multi-Factor Authentication (MFA):** Required for admin operations and first-time logins

### Error Handling

**Standard Error Response (4xx/5xx):**
```json
{
  "success": false,
  "statusCode": 400,
  "message": "Descriptive error message",
  "errors": [
    "Specific error detail 1",
    "Specific error detail 2"
  ]
}
```

### Data Validation & Constraints

- All input fields validated against type specifications
- Required fields cannot be null or empty
- Date/time fields must follow ISO 8601 format
- Medical values must fall within safe clinical ranges
- National IDs validated for uniqueness across system

### Rate Limiting

- 100 requests per minute for standard users
- 500 requests per minute for admin operations
- 10 requests per minute for device API keys
- Automated lockout after 5 failed authentication attempts within 15 minutes

### API Security Considerations

1. **HTTPS/TLS:** All endpoints require encrypted transport (TLS 1.3 minimum)
2. **CORS:** Cross-origin requests restricted to approved medical facility domains
3. **Input Sanitization:** All request parameters sanitized against SQL injection and XSS attacks
4. **Audit Logging:** All API calls and critical operations logged with timestamp, user ID, and action details
5. **Data Privacy:** HIPAA compliance enforced; sensitive medical data encrypted at rest and in transit

### Versioning

Current API version: **v1.0**
Versioning strategy: URL-based (/api/v1/...)
Backward compatibility maintained for minimum 2 major versions
